## 需要展开的几条

### D7 → D21：为什么把 OCR 默认引擎反转了

原设计认为"系统内置 OCR 零体积、够用"，把离线包当可选增强。M0 顺手实测推翻了前提：

- 测试机是中文系统，`OcrEngine.AvailableRecognizerLanguages` 只有一个引擎：`zh-Hans-CN`
- 这个中文引擎**能读英文**，但会吞空格：`The quick brown fox jumps over the lazy dog.` → `The quick brown foxjumps over the lazy dog.`；`3.14159` → `3 ． 141 59`
- 11–30px 字号都认得出，但 18px 以上开始出现 `PIease`（l→I）、`fO r` 这类混淆
- 白字黑底（深色模式）识别正常，这一点没问题

结论：系统 OCR 可以用来"零下载先跑起来"，但让它当默认路径会把译文质量的天花板压得很低。因此反转为离线包承担主力，系统 OCR 作为降级与快启路径。

代价是安装包体积从 5–15MB 变成"主包仍是 5–15MB + 首次启用下载约 40–70MB"，这是可接受的：**下载是首次一次性成本，识别质量是每次使用的成本。**

### D16：命名为什么必须拆成两层

GitHub 官方文档（《创建新仓库》中文页，2026-10-21 更新）规定仓库名不得超过 100 字符、只能含 ASCII 字母数字与 `.` `-` `_`。因此"一眼"不能作仓库名——真填中文要么报错，要么 URL 被百分号编码成乱码。

⚠️ 分歧标注：有第三方中文教程站称"GitHub 允许中文仓库名"，与官方文档直接矛盾，以官方为准。

最终：仓库 `YiYan-Glasslate`，显示名「一眼 Glasslate」，slogan「英文？一眼的事。」。

查重方法：`in:name` 搜索 + 直接访问 `github.com/<用户名>/<仓库名>` 试探 404。搜索是关键词/子串匹配，不是严格模糊匹配，所以两步都要做。

### D23：SmartScreen 是已知成本，不是缺陷

未签名的 exe 从网络下载后运行会触发 SmartScreen。处理方式：

- README 写清楚"更多信息 → 仍要运行"
- 不宣称这是 bug，也不做奇怪的绕过（比如教用户关 SmartScreen，那是害人）
- 等 M5 评估证书成本后再决定是否签名

### D25：抓屏为什么不用"隐藏自己"

原设计认下"隐藏窗口 → 抓屏 → 恢复"的一帧闪烁。M0 发现更好的做法：给玻璃窗设 `WDA_EXCLUDEFROMCAPTURE`，之后 DWM 合成时它会自动从截屏内容里被剔除，`BitBlt` 直接拿到的就是干净的背景。

- 好处：零闪烁、零往返（不用 hide/show）、重译时窗口不用消失
- 限制：需要 Windows 10 2004+；更早系统上该标志等同 `WDA_MONITOR`，行为不同
- 注意：官方明示它不是安全/DRM 特性，挡不住手机拍屏

### D27：坐标口径的实测依据

在同一台机器、同一时刻：

```
Tauri  outer_position = (710, 374)   outer_size = 1140 × 780
Win32  GetWindowRect  = (710,374) - (1850,1154)  → 1140 × 780
```

逐像素相同 → Tauri 返回的就是物理像素，`scale_factor()`（1.5）是"物理/逻辑"的倍率，不要再乘一次。

窗口从 150% 屏移到 100% 屏时：物理矩形从 1140×780 变成 760×520，**逻辑尺寸始终 760×520**。所以抓屏矩形必须每次现取，缓存必然错。
