# 一眼 Glasslate · 阶段与任务计划

- **最近更新**：2026-10-26
- **当前阶段**：M0 已完成 → M1 待开工
- **估算口径**：单人 + AI 辅助的实际耗时估算，不含需求讨论

| 阶段 | 目标 | 状态 |
| --- | --- | --- |
| **M0** | 最小技术验证：透明置顶 / 点击穿透 / DPI 坐标 / 区域抓屏 | ✅ 完成（2026-10-26） |

**为什么 M0 必须单独存在**：透明窗口、点击穿透、DPI 坐标、区域抓屏是四件最容易翻车的地基，且互相独立。跳过 M0 直接做 M1，很可能到 M2 才发现透明不生效，届时前面的 UI 全要重写。事后看，这个判断是对的——M0 里至少有两项的**实现方案**和原设想不同。

## M1 · 主链路（约 16 小时）

**目标**：跑通「框选 → 抓屏 → 系统 OCR → 阿里云翻译 → 普通弹窗显示译文」。**本阶段刻意不做原位覆盖渲染**，先用最普通的弹窗把 OCR 与翻译两个外部依赖的坑全部踩完。

**前置**：M0 结论已回写（尤其 T2 的穿透轮询方式、T3 的物理像素口径、T4 的抓屏方案）。

### T5 · 项目脚手架与窗口体系（2h）

- 三窗口共存：选区遮罩窗、玻璃窗、设置窗；托盘图标与单实例
- 接入 Tauri 官方 `single-instance`、`tray-icon`、`global-shortcut` 三个插件
- 窗口按需创建销毁，而非全部常驻
- **验收**：启动后只在托盘可见、无主窗口；托盘菜单能唤起三个窗口；重复双击 exe 不开第二个进程
- **坑**：窗口配置在 `tauri.conf.json` 与运行时 API 两处都能设，**只在一处设**，否则互相覆盖很难查；多窗口用不同 HTML 入口，不要用 URL 参数分流

### T6 · 选区遮罩窗与框选（2.5h）

- 全屏、置顶、半透明黑遮罩；鼠标按下-移动-松开绘制选框；松手后回传矩形并销毁遮罩
- **验收**：多显示器铺满、可跨屏拖框；实时尺寸提示；松手无残影；Esc 取消不留窗口；矩形与 T3 口径一致（物理像素、无偏移）
- **坑**：①遮罩自身会入镜，必须"销毁遮罩 → 等一帧 → 再抓屏"；②全屏置顶窗在 Windows 上偶尔抢不到焦点导致 Esc 失效，需显式激活

### T7 · OCR 接入（3h）

- `windows` crate 调 WinRT `OcrEngine`；位图转 `SoftwareBitmap`；异步 API 的阻塞/等待方式
- **验收**：对含三四行英文的截图，返回每行文本 + 矩形 + 词级坐标；坐标与像素位置对得上；记录 800×400 图的实测耗时
- **实测参考（M0 顺手测得）**：`BitmapDecoder.GetSoftwareBitmapAsync()` 返回 `Bgra8 / Straight`（**不是** premultiplied），`RecognizeAsync` 直接接受——只有自己创建 `SoftwareBitmap` 时才需要关心 alpha 模式。中文系统只有 `zh-Hans-CN` 引擎，可用英语料但会吞空格
- **坑**：语言包缺失时 `TryCreateFromLanguage` 返回空，必须做能力检测并给明确提示；WinRT 异步不要在 UI 线程同步等待

### T8 · 阿里云机器翻译接入（3h）

两条路径，按顺序尝试：

- **路径 A（默认引擎）**：`TranslateGeneral`，RPC 风格，手写签名——参数字典序、URL 编码特殊（空格 `%20`、`*` 为 `%2A`、`~` 不编码）、拼待签串、HMAC-SHA1、Base64。**这是全流程最容易 400 的一步**
- **路径 B（备用）**：百炼 OpenAI 兼容端点 + Qwen-MT，只需 `Authorization: Bearer`

**执行建议**：先用 Python 或 curl 把路径 A 的签名跑通，确认能拿到译文，再移植到 Rust。直接写 Rust 时出错无法区分是签名错还是代码错。路径 A 卡超过半天就切路径 B 打通链路，M2 再回来补。

- **验收**：同一段英文稳定出译文；连续 20 次不触发限流；Key 错误 / 额度用尽 / 无网三种情况返回可区分错误
- **坑**：`SignatureDoesNotMatch` 会回带服务端期望的待签串，**打印出来逐字符比对**是最快定位法；AccessKey 用只授予 `AliyunMTFullAccess` 的 RAM 子账号

### T9 · 主链路串联与结果显示（2h）

- 按数据流串 `hotkey → capture → ocr → translate → 显示`；本阶段用普通弹窗显示原文 + 译文
- **验收**：快捷键到译文 3 秒内；OCR 无结果提示"该区域没有识别到文字"；翻译失败时**原文仍然显示**并给原因；连按不崩溃不重复开窗
- **坑**：三步都是耗时操作，必须异步且可取消；用自增序号校验，防止旧结果覆盖新结果

### T10 · 配置持久化与三步引导（2h）

- SQLite（Tauri `sql` 插件）或先 JSON；存 `%APPDATA%`；引导三步：选引擎 → 粘 AccessKey → 试翻一张
- **验收**：重启不需要重填；配置在 AppData 而非程序目录；引导 ≤1 分钟；`.gitignore` 覆盖配置文件且 `git status` 看不到
- **坑**：**AccessKey 是明文存本地**，README 必须如实说明，并建议用只有机器翻译权限的 RAM 子账号；不要宣称"加密存储"除非真的做了

### T11 · 错误处理与状态提示（1.5h）

六类必须覆盖：无网络 / AccessKey 无效 / 免费额度用尽 / OCR 语言包未安装 / 区域无文字 / 抓屏失败（受保护内容）

- **验收**：每类都给"发生了什么 + 该怎么办"，而不是抛错误码或静默失败；额度用尽时附控制台链接
- **坑**：`SignatureDoesNotMatch`、`Forbidden.RAM`、`Throttling.User` 必须单独映射成人话

### M1 完成判定

能稳定地框选任意一块英文，3 秒内在弹窗看到原文与译文；六类异常都有可读提示；重启后不需要重填 AccessKey。

**做完 M1 需要回写本文档的三件事**：① OCR 实测耗时与语言包检测结论；② 路径 A 还是 B，签名坑记录；③ 异步取消方案（序号校验还是别的）。

### M1 进展（2026-10-26 晚，T5–T7 已实现，T8–T11 未开始）

**已跑通并验证**：

| 项 | 结果 |
|---|---|
| 三窗 + 托盘 + 单实例 + 全局快捷键 | Alt+Q 唤起遮罩正常；托盘菜单可用 |
| 遮罩框选 | 全屏 4480×1600 覆盖、拖框、Esc 取消；`phys = geo.x + cssX * dpr` 换算在 150% 缩放的主屏正确 |
| 抓屏 | GDI `BitBlt(SRCCOPY\|CAPTUREBLT)`，一次 16–21ms（1320×210 与 1140×780 都在这区间） |
| OCR | 中文引擎读英文：4 行英文 → 136ms；已知缺陷与 M0 一致（`tool`→`t00 上`、`on`→`0 n`、`Tap`→`Ta p`、`2.14.0`→`2 ． 14 ． 0`） |
| 无边框 | `tauri.conf.json` 的 `decorations:false` **在 Windows 上不生效**，必须在 `setup` 里再调一次 `set_decorations(false)` + `set_shadow(false)` |

**踩到的坑（已写进代码注释）**：

1. **`decorations: false` 双重设置**：配置文件里写了、窗口仍有 `WS_CAPTION`，运行期再设一次才掉。
2. **`emit_to` 会丢事件**：Rust 侧 `emit_to(overlay, "overlay-ready", ..)` 常早于遮罩 webview 注册监听 → 遮罩"看着没反应"。改成前端 `await refreshGeo()` 后自己点亮暗层，事件只用于通知。
3. **透明窗口的暗层很难用肉眼验证**：0.28 的黑色暗度在深色壁纸上几乎看不出来，临时换成 `rgba(255,0,0,0.5)` 才确认"遮罩其实一直在正常渲染"。
4. **`[hidden]` 被 `display` 顶掉**：给空态/结果块设了 `display:flex` 后 `hidden` 属性失效，两者同屏。加 `[hidden]{display:none !important}` 修掉。
5. **别在用户正在用的机器上做鼠标自动化验证**：`SetCursorPos` 会和真人抢光标，拖拽被切成"按下即抬起"。改用 `GLASSLATE_SELFTEST="x,y,w,h"` 环境变量让 app 自己抓一块区域跑 OCR，结果写日志——不需要鼠标就能验证 capture→OCR。
6. **`GLASSLATE_CAPTURABLE=1`**：默认所有窗口都设 `WDA_EXCLUDEFROMCAPTURE`，于是截图工具（包括我们自己的 M0 探针）都看不到 app 自己。调试时才置这个变量放行。

**开发机阻塞（重要，换机器必读）**：Windows 11 的 **Smart App Control（SAC）在强制模式下会拦下所有「新编译、无签名」的 exe**（`os error 4551 / An Application Control policy has blocked this file`），连 `rustc hello.rs` 出来的 30KB 小程序都跑不起来。本机 2026-10-26 20:05 起进入这个状态，已把 `HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy\VerifiedAndReputablePolicyState` 由 1 改为 0（需重启生效）。**换机器开发时先确认 SAC 状态**，否则会以为是自己代码的问题。

## M2 · 差异化核心（估 20–25h）

这一阶段才真正做"看起来像这个项目"的东西。

- 覆盖渲染层：段落聚合 → 抹除块 → 译文回填 → 字号自适应（见 [DESIGN.md](DESIGN.md) 第四节）
- 玻璃窗常驻与矩形记忆（注意：矩形每次现取）
- 悬停工具条（Rust 侧轮询，M0/T2 已验证）
- 深色 / 浅色 / 跟随系统三档主题
- 背景采样与降级策略（先用 Python 调阈值，再移植）

**完成判定**：对一段 3–5 行的英文，译文出现在原文位置、原文不可见、背景不违和；鼠标移开工具条消失；深浅色不突兀。

## M3 · 交互完整度（估 12–16h）

- 隐形悬挂（透明 + 穿透，译文仍可见）

- 多窗并存与焦点管理

## M5 · 收尾（估 12–16h）
